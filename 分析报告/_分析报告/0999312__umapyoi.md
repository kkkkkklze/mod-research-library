## 4. 核心系统

1. **数据驱动角色（UmaData）**：`registry/umadata/UmaData.java` 是纯 `RecordCodecBuilder` 数据类（identifier / ranking / property / maxProperty / propertyRate / uniqueSkill / surface_aptitude / distance_aptitude / position），注册进**数据包注册表** `umapyoi:umadata`；实例状态则全部存在 **ItemStack 的 NBT** 上——`utils/UmaSoulUtils.java` 提供了 40+ 个静态 `get/set`（name、property[5]、maxProperty、extraProperty、motivation、growth、skills ListTag、selectedSkill、actionPoint、physique、learningTimes）。"模板走注册表、成长走 NBT" 是其核心分层。
2. **训练系统（TrainingSupport + SupportCard）**：`registry/training/TrainingSupport.java` 是可继承的行为对象注册表（`applySupport(ItemStack soul, RandomSource, SupportStack)` 返回 bool），子类 `StatusSupport / RandomStatusSupport / ExtraStatusSupport / SkillSupport / BorealisSupport`；`registry/training/card/SupportCard.java` 是数据包注册的卡面（ranking / type / supports: SupportEntry / supporters / max_damage），运行时 `getSupportStacks()` 把 `SupportEntry` 解析成 `SupportStack`。扩展点在 `events/ApplyTrainingSupportEvent.java`、`ApplyFactorEvent.java`。
3. **赛程系统（Race / RaceField / RaceTag）**：`Race.java` 用 Codec 描述 ranking、length、time、year 集合、surface、field、attrCorrection、referenceLevel、allowStatus、exclusive、laterThen、afterRace；`isAvailableToUmaSoul` 用 `last_attend_time` 与 `year.ordinal()*24 + time` 做"游戏内日历"门禁，`getUmaFactorCorrection` 把 5 维属性按 `Position` 系数、`Distance/Surface` 适配、`Motivations` 倍率折算成评分，`isPassed` 与 `referenceLevel` 比较。`RaceField` 支持 `CONST_ADAPTIVE`（按距离/场地自动选场地）、`Surface/Distance.ADAPTIVE`（依 UmaSoul 属性自适应），见 `Race.java:64-99`。
4. **UmaSoul 的 Curios 集成与渲染**：`curios/UmaSoulCuriosWrapper`、`UmaSuitCuriosWrapper` 提供 stack handler；渲染走 `client/renderer/*` + `mixin/client/{HumanoidArmorLayerMixin,ElytraLayerMixin,ItemInHandLayerMixin}` 在 HEAD 注入并 cancel，实现"穿外套即改模型/手臂/鞘翅"。
5. **槽位/IO 抽象**：`inventory/*ItemHandler`（`UniversalIOItemHandler`、`TerminalResultHandler`、`ThreeGoddessItemHandler`、`CommonItemHandler`）+ `container/*Menu` 支撑训练台、退役登记、抽卡结果等 GUI。

## 5. 网络 / 数据驱动 / 配置 / datagen

- 网络：`network/NetPacketHandler.java` 用 Forge `SimpleChannel`，协议 `"1.0"`，4 个包 `UseSkillPacket / SelectSkillPacket / SetupResultPacket / EmptyResultPacket` **全部 PLAY_TO_SERVER**，统一 `.encoder(...).decoder(...).consumerNetworkThread(...)`（行 22-33）。
- 数据驱动：`events/handler/SetupEvents.java:24-31` 用 `DataPackRegistryEvent.NewRegistry` 注册 6 张数据包注册表：`umadata / support_card / cosmetic / races / race_field / race_tag`（codec 同时用于网络同步）；另有 `umasoul` 配方 ingredient 的 `RegisterEvent` 注册（行 33-37）。内置数据由 datagen 生成（见下），运行时通过 `UmapyoiAPI.getXxxRegistry(level)` 访问，客户端走 `utils/ClientUtils` 的本地缓存实例。
- 配置：`UmapyoiConfig.COMMON_CONFIG` / `CLIENT_CONFIG` 两个 Forge TOML。
- datagen：`data/DataGen.java`（`GatherDataEvent`）用 `RegistrySetBuilder` 生成 `data/builtin/{UmaDataRegistry, SupportCardRegistry, CostumeDataRegistry}` 的内置数据包条目，并输出 blockstate / item model / lang（1106 行）/ sound / 掉落表 / 物品·方块·POI 标签 / 配方；还含兼容 provider `BetterCombatProvider`、`TFCFoodDataProvider`。

## 7. 值得学的 5 条具体做法

1. **Codec 化的数据包注册表承担"角色模板"，NBT 承担"实例成长"**：`UmaData.java:28-43` + `utils/UmaSoulUtils.java`——适合任何"召唤物/装备/坐骑有基础模板 + 可养成"的设计。
2. **自适应枚举值（ADAPTIVE / CONST_ADAPTIVE）做内容分流**：`Race.java:64-99` 让一个字段同时表达"固定值"和"依属性动态计算"，减少注册表条目爆炸。
3. **注册表项带 Builder 与 referenceLevel 缺省推导**：`Race.RaceBuilder.create()` 按 `RaceRanking` 自动给难度基准（`Race.java:418-429`），写内置数据时只填必要字段——适合批量内容物。
4. **Forge 事件做成对外扩展点**：`events/` 下 20+ 个自定义 Event（`FindUmaSoulEvent.Pre/Post`、`ApplyTrainingSupportEvent`、`SkillEvent`、`GachaEvent`、`RetireEvent`），配合 `api/UmapyoiAPI.getUmaSoul()` 的 Pre→读取→Post 三段式，第三方可完全替换"角色从哪来"。
5. **条件 mixin + 软依赖隔离**：`ParcoolMixinPlugin` + `ModList.get().isLoaded()` 判断（`Umapyoi.java:64-69`），让可选联动不污染主流程——适合多兼容附属。
