## 3. 入口与注册

`Main.java`：`@Mod(Main.MODID)`，构造里挂两个 mod 事件 + 注册：

```java
// Main.java:53-61
IEventBus modEventBus = FMLJavaModLoadingContext.get().getModEventBus();
modEventBus.addListener(this::setup);
modEventBus.addListener(this::setupComplete);
MinecraftForge.EVENT_BUS.register(this);
SOUNDS.register(modEventBus);
GLMRegistry.GLM.register(modEventBus);
ModLoadingContext.get().registerConfig(ModConfig.Type.COMMON, MMLibConfig.COMMON_CONFIG);
```

- 注册内容极少：`DeferredRegister<SoundEvent> SOUNDS`（只注册 `presented_by_zaia` 一个音效）+ `GLMRegistry.GLM`（`DeferredRegister<Codec<? extends IGlobalLootModifier>>` 注册 `add_loot_table`）
- **`setupComplete`（`FMLLoadCompleteEvent`）里改写原版静态字段**是本库最典型的"库式"操作（`Main.java:67-75`）：`Chicken.FOOD_ITEMS = CompoundIngredient.of(Chicken.FOOD_ITEMS, Ingredient.of(CommonTags.CHICKEN_FOOD))`，对 Pig / Strider（FOOD_ITEMS + TEMPT_ITEMS）/ Ocelot / Cat / AbstractHorse 同样处理——**用 tag 统一给原版动物喂食表扩展**，是所有下游 mod 都能受益的做法
- 无 GUI、无方块/物品注册、无网络注册（未发现任何 SimpleChannel/PacketDistributor 注册）

## 4. 核心系统

1. **基岩版（Bedrock）模型加载与渲染**（最大子系统）：`client/model/BedrockModelResourceLoader` 继承 `SimpleJsonResourceReloadListener`，资源重载时清空并重建 `ClientUtil.MODEL_MAP`；`ClientUtil.loadModel()`（`utils/ClientUtil.java:22-52`）按 `format_version` 分流——`1.10.0` 走 `getGeometryModelLegacy()`，`>= 1.12.0` 走 `getGeometryModelNew()`，字段为空则打 warn 返回。支持类：`bedrock/BedrockModel`(接口)、`BedrockPart`/`BedrockCube`/`BedrockPolygon`/`BedrockVertex`/`BedrockVersion`；POJO：`pojo/{BedrockModelPOJO, GeometryModelLegacy, GeometryModelNew, BonesItem, CubesItem, FaceItem, FaceUVsItem, Description}`；渲染封装：`BedrockEntityModel<T extends Entity> implements BedrockModel`（可直接当 `EntityModel` 用）、`BedrockHumanoidModel`、`BedrockArmorModel`/`StandardArmorModel`、`BedrockModelResourceLoader` + `utils/BedrockAnimationUtils`。
2. **配方抽象与"Gson 全能序列化"**：`recipe/AbstractRecipe implements Recipe<RecipeWrapper>`，公共字段 `group/experience/recipeTime` 用 Gson `@Expose` 标注；`recipe/AbstractRecipeSerializer<T>`（`AbstractRecipeSerializer.java:16-37`）把 JSON/网络读写全交给 `DataGenUtil.NETWORK_GSON`，网络用 `buffer.writeUtf(gson.toJson(recipe))`——简单粗暴但对 1.20.1 的小型机器配方够用。`json/AbstractSerializer` 内置 `ItemStack/Ingredient/FluidStack/ChanceResult/FluidIngredient` 序列化器 + `NonNullListDeserializer`，配置为 `excludeFieldsWithoutExposeAnnotation()`。
3. **流体工具**：`fluid/FluidIngredient`（`abstract class implements Predicate<FluidStack>`，静态工厂 `fromTag/fromFluid/fromFluidStack`，字段 `amountRequired`、`matchingFluidStacks` 缓存匹配结果、`fixFlowing()` 处理 FlowingFluid）+ `fluid/ConsumerFluidTank extends FluidTank`（构造传 `Consumer<FluidStack>`，`onContentsChanged()/setFluid()` 自动回调，用于 BE 同步）+ `fluid/FluidHelper`。
4. **食物系统（含 TFC 兼容）**：`item/info/FoodInfo` 用 Builder 模式承载 name/amount/calories/wolfFood/alwaysEat/eatTime/compostChance + **TFC-TNG 的 water/grain/fruit/veg/meat/dairy/decayModifier/heatCapacity/cookingTemp**（`isNonDecaying = decayModifier <= 0`、`heatable = cookingTemp >= 0`）；`item/IFoodLike` 接口提供 `getFoodInfo()/shouldAddEffectTooltips()/addEffectTooltips()`（完整复刻药水的"效果 + 属性修正"WhenDrank 提示逻辑）；实现类 `ItemFoodBase`/`ItemDrinkBase`/`ItemFoodSeeds`。
5. **村民/交易扩展（mixin + 自定义 listing）**：`mixin/VillagerMixin`（`@Inject` `wantsToPickUp` TAIL 可取消、`countFoodPointsInInventory` TAIL、`eatUntilFull` HEAD）配合 `mixin/VillagerInvoker`（`@Mixin(Villager.class)` 接口 + `@Invoker("hungry")`/`@Invoker("countFoodPointsInInventory")`）；`mixin/TradeWithVillagerMixin` 在 `tick` TAIL 让农民把多余食物分给同伴（`throwHalfStackInvoker`）；`villager/` 提供 `RandomItemOrderItemListing`/`RandomPriceOrderItemListing`/`RandomPriceSellItemListing` 三种交易项。
6. **datagen 与战利品**：`data/` 下 5 个抽象 Provider 基类（`AbstractBlockStateProvider`/`AbstractItemModelProvider`/`AbstractLangProvider`/`AbstractRecipeProvider`/`AbstractConditionalDatapackEntriesProvider`），`AbstractLangProvider` 预置 `addAdvTitle/addAdvDesc/addSubtitle/addBiome/addDeath/addTooltip` 等语法糖；`data/loot/AbstartctBlockLoot`（原文拼写如此）、`LootTableProviderBuilder`；`data/loot/modifier/AddLootTableModifier extends LootModifier`（用 `RecordCodecBuilder` + `Suppliers.memoize`，代码注释标明 "Credits to Commoble"）实现"命中条件时把另一张战利品表的内容追加进来"，`GLMRegistry` 负责注册其 Codec。

## 5. 网络 / 数据驱动 / 配置 / datagen

- 网络：**无自有网络通道**；唯一的网络化行为是把配方对象 Gson 成字符串塞进 `FriendlyByteBuf`（`AbstractRecipeSerializer.fromNetwork/toNetwork`）
- 数据驱动：三条线——(a) 原版 datapack + datagen Provider 基类；(b) GlobalLootModifier JSON（`add_loot_table`）；(c) **基岩模型 JSON**（`SimpleJsonResourceReloadListener` 读取，支持 1.10.0 / 1.12.0 两种 format_version）
- 配置：`MMLibConfig` 手写 `ForgeConfigSpec`，只有一个 `general.welcome_info` 布尔（默认 false）；配置在 `Main` 构造注册为 COMMON
- datagen：即上述 Provider 抽象，下游 mod 只需继承并填内容

## 6. Mixin

- 配置路径：**`mixins.mmlib.json` 通过 `build.gradle:131` 的 jar manifest `"MixinConfigs": "mixins.mmlib.json"` 声明**，并由 mixin gradle 生成 `mixins.mmlib.refmap.json`（`build.gradle:19`）；运行配置额外传 `-mixin.config=mixins.mmlib.json` 且开启 `mixin.debug.export`/`mixin.env.remapRefMap`
- **注意：该 json 文件不在本快照的 `src/main/resources` 中**（该目录只有 `META-INF/accesstransformer.cfg` 与 `mods.toml`），mixin 注册项的完整列表**未确认**
- mixin 类 4 个（均在 `cn.mcmod_mmf.mmlib.mixin`）：`VillagerMixin`（hook `Villager.wantsToPickUp` / `countFoodPointsInInventory` / `eatUntilFull`）、`VillagerInvoker`（`@Invoker hungry`、`countFoodPointsInInventory`）、`TradeWithVillagerMixin`（hook `TradeWithVillager.tick` TAIL）、`TradeWithVillagerInvoker`
- 另有条件 mixin：`client/compat/ar/ARMixinPlugin implements IMixinConfigPlugin`，`shouldApplyMixin` 用 `LoadingModList.get().getModFileById("acceleratedrendering") != null` 判断是否装了渲染优化 mod（配合 `AcceleratedBedrockPart`）

## 7. 值得学的 5 条具体做法

1. **`FMLLoadCompleteEvent` 里改写原版静态 Ingredient 字段**：`Chicken.FOOD_ITEMS = CompoundIngredient.of(原值, Ingredient.of(TagKey))`——不改 mixin 就给原版动物加 tag 食物（`Main.java:67-75`）。1.20.1 Forge 上给原版实体做 tag 扩展都可套用。
2. **`@Invoker` 接口与 `@Inject` 类分离**：`VillagerMixin implements VillagerInvoker`，注入代码里直接 `this.hungryInvoker()` 调私有方法，无需 `@Shadow` 反射（`mixin/VillagerInvoker.java`）。
3. **Gson + `@Expose` 统一"配方 ↔ JSON ↔ 网络"三态序列化**：一个 `AbstractRecipeSerializer` 覆盖 datagen/加载/联机三条路径（`recipe/AbstractRecipeSerializer.java:16-37`），适合快速做机器配方。
4. **基岩版模型 JSON 加载器（1.10.0 / 1.12.0 双格式）**：`SimpleJsonResourceReloadListener` + `format_version` 分支判定 + `ClientUtil.MODEL_MAP` 缓存，是 GeckoLib 之外"自带模型格式"的轻量范本（`utils/ClientUtil.java:22-52`）。
5. **配置/资源/兼容三处都做软失败**：模型缺字段打 warn 返回而不抛异常；`ARMixinPlugin` 用 `LoadingModList` 判 mod 存在；`migrateConfig` 式兼容——库模组应尽量"下游不装任何东西也不炸"。

## 8. 库 / API 说明

**没有独立 `api` 包**，公开面就是 `cn.mcmod_mmf.mmlib.*` 全部类，下游 mod 直接 `compileOnly` + `publishToLocalMaven` 本地仓库引用（README 明示）。主要扩展点：
- `registry.ItemDataRegistry`（`getID()` / `getItem(Item)` / `getItem()` / `<T extends ItemDataRegistry> Codec<T> getCodec()`）+ `registry.ItemRegistryUtil.mapOfKeys(enumClass, mapper)`：enum → 数据映射的注册范式
- `recipe.AbstractRecipe` / `AbstractRecipeSerializer` / `ChanceResult.rollOutput(rand, fortuneLevel)`：带概率产出与"时间/经验"字段的机器配方基类
- `fluid.FluidIngredient` / `ConsumerFluidTank` / `FluidHelper`
- `item.IFoodLike` + `item/info/FoodInfo`（含 TFC 营养参数）：跨 mod 的食物数据统一描述
- `block.BaseCropBlock` / `HighCropBlock` / `Age3CropBlock` / `FacingSlab`；`block/entity.SyncedBlockEntity`（同步 BE 基类）/`HeatableBlockEntity`/`AnimatableBlockEntity`
- `entity.EntityBullet`：弹射物抽象基类（damage / ignoreInvulnerability / maxTick / knockbackStrength / ticksSinceFired）
- `data.*` 五个 Provider 基类 + `data/loot/modifier` GLM；`client.model.Bedrock*` 全套模型加载/渲染；`utils.*`（`TagUtils`/`I18nUtils`/`LevelUtils`/`VillagerUtils`/`DataGenUtil`/`BedrockAnimationUtils`/`ClientUtil`）；`CommonTags` 集合标签
